# Contributing to VulnGuard

## Before making changes
1. Read README.md and docs/development-standards.md.
2. Check the current Git status.
3. Create a focused branch for your change.

## Branch naming
- feat/short-description
- fix/short-description
- docs/short-description
- test/short-description

## Commit message examples
- feat: add repository registration endpoint
- fix: handle scanner timeout correctly
- test: cover risk scoring edge cases
- docs: clarify local development setup

## Pull request expectations
- Explain the problem and proposed solution.
- Keep changes focused and reviewable.
- Include tests for changed behavior where appropriate.
- Document configuration changes.
- Never include credentials or sensitive scan output.

## Security reports
Do not publish real credentials, private repository content, or
unredacted vulnerability evidence in issues or pull requests.
Use sanitized examples and responsible disclosure.
